# Agent Session Lossless Transcript Design

## Goal

For Agent sessions created after this change, retain every producer output chunk until the user explicitly closes or abandons the session. Keep the live terminal responsive with bounded memory and rendering work. A renderer backlog, application restart, remote reconnection, or host-session reattach must not turn retained output into an unrecoverable gap.

## Scope and Assumptions

- The feature applies to `kind: 'agent'` sessions only. Ordinary terminal sessions keep their current bounded replay and scrollback policy.
- Retention starts when a new Agent session is created after deployment. Output that an older version already discarded cannot be reconstructed.
- The archive remains available until the UI session is explicitly abandoned. Existing stale-session pruning may remove its archive only after the corresponding persistent session record is removed.
- A disk write failure is a visible degraded state, never a silent claim that the transcript is complete.
- Existing 64 KiB / 4 MiB replay buffers remain live recovery tails. They are no longer the authoritative full transcript.
- Active Agent output is a P0 correctness invariant. Transcript retention must never suppress, rewrite, delay past loss, or otherwise change terminal control sequences used by an interactive Agent TUI.

## Rejected Approaches

### Raise Existing Limits

Increasing xterm scrollback, replay, and metadata limits delays truncation but leaves a hard cap and worsens renderer memory pressure. It does not protect output produced while the application is disconnected.

### Keep the Complete Transcript in Renderer State

Holding all output in React, Zustand, or xterm memory ties transcript retention to a single renderer lifetime and reintroduces the rendering stalls this work is meant to prevent.

### Main-Process-Only Archive

Capturing only `SessionManager` events protects output while the application is connected, but misses data generated by persistent tmux, supervisor, or remote sessions after the application disconnects.

## Selected Architecture

Use append-only transcript archives at the output producer, with a bounded live display path and a paged transcript read path.

```text
Local PTY / tmux sidecar / local supervisor / remote helper
  -> append UTF-8 bytes to a per-session archive
  -> append bounded replay tail
  -> batch live output
  -> SessionManager
  -> bounded xterm queue

Renderer transcript drawer
  -> paged session transcript request
  -> local archive reader or supervisor / remote helper RPC
```

### Archive Ownership

`SessionTranscriptArchive` is a main-process service for local direct-PTY sessions. It owns directory creation, append serialization, file permissions, paged reads, deletion, and diagnostics. It stores archives outside `PersistentAgentSessionRecord.metadata`; SQLite remains a compact session index and lifecycle authority.

Local supervisor and remote helper sessions archive at their own producer process. Each generated helper owns the same append-only archive behavior and exposes a narrow transcript RPC surface. The main process proxies that surface without copying full history through a replay payload.

Persistent tmux sessions need a host-side pipe writer. A tmux host adapter starts an idempotent, managed `pipe-pane` writer for the session and stops it during host teardown. The writer appends to the same local archive format while the Electron renderer and main process are absent.

### Identity and Lifecycle

- Archives use a validated backend session identifier in their filename. UI session IDs remain in the persistent-session index and map to backend IDs during cleanup.
- On Agent-session creation, allocate the archive before the producer starts. A failed allocation aborts creation with an explicit error instead of running an unarchived session.
- On attach and reconnect, the producer returns the normal bounded replay for fast terminal hydration. The drawer reads the full archive independently.
- On `agentSession.abandon`, delete the persistent record and the matching local or remote archive. A delete failure is retried and recorded in diagnostics.
- Exited sessions keep their archive until abandonment, allowing inspection and export after process exit.

### Data Format and Unicode Safety

Archives contain raw UTF-8 output bytes in arrival order. No replay-size limit applies to the archive. Appends are serialized per session so chunks cannot interleave.

Paged reads use byte cursors and a streaming UTF-8 decoder. Returned text pages begin and end at valid code-point boundaries. Shared tail helpers replace raw `slice(-limit)` use in replay and persisted snapshots so a retained tail never starts with an orphaned low surrogate.

### Interactive TUI Compatibility

The current Agent transcript mode suppresses alternate-screen and mouse private-mode sequences to keep terminal content in xterm scrollback. That policy is incompatible with interactive Agent CLIs that redraw through alternate-screen buffers and cursor movement. It can leave a partially rendered latest response even when the underlying process produced more output.

The replacement design makes capture passive:

- Archive raw producer bytes before the renderer consumes them.
- Do not suppress or rewrite alternate-screen, cursor, erase, or other rendering control sequences for live Agent sessions.
- Let xterm render interactive TUI output with its native buffer semantics.
- Show historical output through the archive-backed transcript drawer rather than relying on xterm normal-buffer scrollback.
- Keep pointer/input safety as a separate interaction policy; it must not alter output parsing.

### Renderer Behavior

The live terminal remains bounded:

- `SessionOutputBatcher` and xterm write batching continue to coalesce output.
- The xterm queue may protect frame time, but a backlog overflow is recorded as a transcript warning rather than the only copy of data. The archive remains complete.
- `AgentSessionTranscriptDrawer` loads the latest page first and can load older pages on demand. It never loads the whole archive into React state.
- Search is page-oriented in the initial delivery. Export uses a main-process streaming path so it does not build an unbounded browser `Blob`.

### Failure Semantics

- Archive creation, append, read, and delete failures carry a structured transcript health state.
- The session continues to render live output when possible, but the panel shows that complete retention is unavailable.
- Remote helper failures preserve the remote session lifecycle; reconnect retries archive reads and reports the last archive error.
- Main-process cleanup flushes local append queues before session exit notification and before application shutdown.

## Extension Points

| Concern | Owner | Intended extension |
| --- | --- | --- |
| Local archive files | `src/main/services/session/` | `SessionTranscriptArchive` |
| Local direct-PTY capture | `SessionManager` | append before live batch dispatch |
| tmux capture | `session/hosts/` and tmux adapter | managed archive pipe lifecycle |
| Windows persistent sessions | `LocalSupervisorSource.ts` | helper-local archive and RPC |
| Remote persistent sessions | `RemoteHelperSource.ts` | helper-local archive and RPC |
| Cross-process contract | `src/shared/types/`, IPC, preload | paged read, export, health payloads |
| Transcript UI | `components/chat/` | page-based drawer state and degraded-state presentation |
| Retention cleanup | persistent session service | delete archive with abandoned session |

## Test Strategy

1. Pure archive tests prove ordered append, UTF-8-safe page boundaries, atomic creation, retryable deletion, and rejection of unsafe identifiers.
2. Session-manager tests prove each local Agent output is archived before batch delivery and that exit flushes pending archive writes.
3. Supervisor and remote-helper generated-source tests prove output is archived even with no attached client, and that reconnect reads complete pages without using replay as the source of truth.
4. tmux host tests prove the archive pipe is configured idempotently and released during teardown.
5. IPC and preload tests prove only typed page/export requests cross process boundaries.
6. Renderer tests prove latest-first pagination, older-page loading, archive-health feedback, and bounded DOM rendering.
7. TUI compatibility tests feed alternate-screen and cursor-redraw sequences into a live Agent terminal and prove the latest rendered output is complete.
8. Regression tests cover a split-surrogate boundary, a renderer backlog above 8 MiB, an application disconnect followed by output, and explicit session abandonment.

## Acceptance Criteria

- A newly created Agent session can emit more data than replay, scrollback, snapshot, and xterm backlog limits without losing archived output.
- A producer that emits output while the renderer is absent retains that output for a later transcript read.
- Transcript pages and retained replay tails never contain orphaned UTF-16 surrogate code units.
- The renderer never receives an unbounded transcript payload or renders an unbounded number of lines.
- A live interactive Agent TUI can use alternate-screen and cursor redraw without leaving a truncated or partially rendered latest response.
- Closing or abandoning a session removes its archive through the same lifecycle that removes its persistent record.
- Archive failure is observable in diagnostics and UI; the product does not represent the transcript as complete when it is not.
