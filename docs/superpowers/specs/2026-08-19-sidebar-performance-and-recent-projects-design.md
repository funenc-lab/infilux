# 侧栏性能与最近项目渐进加载设计

## 背景

当前导航侧栏和文件侧栏在展开时会修改 `App` 根组件状态，并通过 Framer Motion 逐帧动画 `width`。这会同时触发应用壳重渲染和布局重排。项目数量、文件节点、Agent 会话和终端数量增加后，展开延迟会明显放大。

悬浮导航侧栏还会在 `pointerleave` 时立即关闭。按钮触发 Portal 菜单或切换视图导致 DOM 变化时，指针可能短暂离开侧栏宿主，从而出现点击后侧栏意外关闭。

项目列表目前一次性渲染全部 Repository。视觉上隐藏侧栏不会减少项目节点、预取范围或差异统计范围，长期使用后列表成本持续增长。

## 目标

- 侧栏展开不触发 `App` 根组件重渲染。
- 展开动画只使用 `transform` 和 `opacity` 等合成属性，不逐帧修改布局宽度。
- 与侧栏关联的 Portal 交互不导致侧栏意外关闭。
- 活跃项目始终可见，非活跃项目按最近访问时间渐进展示。
- 隐藏项目不参与 worktree 预取和可见范围差异统计。
- 保留项目分组、搜索、拖拽排序、键盘焦点和远程项目行为。

## 非目标

- 不把 Repository 存储迁移到数据库或新增分页 IPC。
- 不引入虚拟列表依赖。
- 不修改 Agent、终端或会话恢复语义。
- 不改变现有侧栏宽度、主题或视觉层级。

## 侧栏交互架构

新增独立的 `SidebarHoverRevealGroup` 布局控制组件。组件在内部持有悬浮侧栏打开状态，并通过稳定的 `children` 边界隔离导航树，避免打开状态传播到 `App`。

悬浮侧栏宿主始终保持触发轨道宽度。完整侧栏面板使用固定宽度，隐藏和显示只切换 `transform`、`opacity` 与 `pointer-events`。文件侧栏在展开时一次性设置目标宽度，入场和退场只使用水平位移与透明度。

关闭判断同时考虑：

- 指针是否仍位于侧栏宿主；
- 焦点是否仍位于侧栏内部；
- 下一指针或焦点目标是否位于 `SidebarFloatingMenuPortal`；
- 窗口是否失去焦点或页面是否隐藏。

普通按钮点击不会直接关闭侧栏。明确的窗口失焦、指针离开且无关联 Portal、或键盘焦点离开才关闭。

## 最近访问数据

Repository 增加可选字段 `lastAccessedAt`，单位为 Unix 毫秒时间戳。以下入口更新该字段：

- 用户从导航侧栏选择项目；
- 打开路径事件选择已有项目；
- 新增或克隆项目完成后将其设为当前项目；
- 恢复流程将某个项目设为当前选择。

旧数据没有时间戳时保持原持久化顺序作为稳定回退，不批量伪造当前时间。首次访问后写入真实时间戳。路径比较统一使用规范化路径。

## 活跃项目规则

满足任一条件的 Repository 视为活跃：

- 是当前选中的项目；
- 任一所属 worktree 存在运行中的 Agent；
- 任一所属 worktree 存在运行中的终端。

仅存在历史会话但没有当前运行进程，不视为活跃。活跃项目始终进入可见集合。

## 渐进展示规则

首屏显示所有活跃项目，以及最近访问的 8 个非活跃项目。底部“展开更多项目”每次增加 8 个非活跃项目，直到全部显示。

可见预算在所有项目分组间全局计算，分组关系保持不变。最近访问时间只决定哪些非活跃项目进入可见集合；实际行顺序继续使用现有持久化顺序，确保拖拽排序仍然有意义且项目不会在用户操作时跳动。当前批次没有可见项目的分组不渲染。

搜索开启时不应用渐进数量限制，所有匹配项目均可见。外部打开、恢复或深链接选中的项目即使不在当前批次，也强制进入可见集合。

筛选条件、项目集合或分组发生变化时，展示预算重置为首批数量。用户主动展开更多时只增加预算，不改写 Repository 数据。

## UI 与交互细节

“展开更多项目”位于项目滚动列表末尾，不放入固定 Footer，也不使用卡片。它复用现有侧栏行密度，使用 `ChevronDown` 图标、明确的动作标签和弱化的剩余数量，例如 `Show 8 more` 与 `12 remaining`。固定 Footer 继续只承载主要的 `Add Repository` 操作。

按钮使用原生 `button` 语义，支持 Tab 聚焦、可见的 `focus-visible` 状态以及 Enter/Space 激活。新增项目后保持用户当前滚动位置；只有用户明确点击展开时才追加项目，不自动滚动到列表底部。

分组标题的数量继续表示分组内项目总数，而不是当前批次可见数量。这样折叠分组、渐进展示和搜索状态不会让数量含义发生变化。没有进入当前批次的分组暂不显示；搜索时恢复所有匹配分组及其匹配项目。

当前选中项目即使不在最近批次也强制显示。活跃状态变化只改变可见集合，不改变已显示项目的手动顺序；项目在当前交互期间不会因为 Agent 刚刚停止而突然消失。已经显示的项目在本次窗口生命周期内保持显示，预算重置只发生在项目集合、分组或显式搜索条件变化时。

加载更多不使用高度弹簧动画，避免长列表追加时产生连续布局动画。新增行直接进入正常文档流；悬浮侧栏本身继续通过短时 `transform/opacity` 提供方向感，并遵守 `prefers-reduced-motion`。

## 数据流

1. Repository 状态层加载并规范化持久化项目。
2. 项目选择入口调用统一的访问时间更新函数。
3. 纯策略函数接收 Repository、当前选择、worktree 活跃状态、搜索文本、已显示路径和当前预算。
4. 策略函数输出保持手动顺序的可见 Repository、隐藏数量和是否仍可展开。
5. `TreeSidebar` 与 `RepositorySidebar` 只渲染可见集合。
6. worktree 预取和差异统计使用相同可见集合，不为隐藏项目发起请求。

## 组件边界

- `SidebarHoverRevealGroup`：只管理悬浮侧栏显示状态和输入事件。
- `sidebarHoverRevealPolicy`：保持无 DOM 依赖的打开、关闭和宽度策略。
- `recentRepositoryVisibilityPolicy`：负责活跃判断、最近集合选择、稳定展示顺序和批次计算。
- `useRepositoryState`：负责持久化访问时间，不承担展示排序。
- `TreeSidebar`、`RepositorySidebar`：消费策略结果并呈现“展开更多项目”。

## 错误与边界处理

- 非法或非有限时间戳按缺失处理。
- 已删除项目的访问时间随 Repository 删除，不建立并行缓存。
- 远程项目不可加载时仍可按访问时间显示，但不会预取 worktree。
- 搜索无结果沿用现有空状态。
- 活跃项目数量超过 8 时全部显示，不挤占非活跃项目的首批预算。
- 项目少于或等于首批数量时不显示展开按钮。

## 测试策略

- 策略单元测试：最近访问集合、稳定展示顺序、活跃项目保留、全局预算、强制显示、已显示项目保留和搜索绕过限制。
- 组件集成测试：悬停状态变化不重渲染子树、Portal 指针和焦点转移保持打开、真实离开关闭。
- 文件侧栏测试：动画对象不包含 `width`、`height`、`left` 或 `right`。
- TreeSidebar/RepositorySidebar 测试：展开更多按 8 个递增，隐藏项目不进入预取输入。
- 存储测试：旧 Repository 数据兼容，访问后时间戳持久化。
- 完整验证：相关 Vitest、`pnpm typecheck`、Biome 和项目质量门禁。

## 验收标准

- 悬浮侧栏打开/关闭不增加导航树子组件渲染次数。
- 两个侧栏的展开动画不包含布局宽度动画。
- 点击侧栏按钮或进入关联菜单不会意外关闭侧栏。
- 首屏显示所有活跃项目和最多 8 个非活跃项目。
- “展开更多项目”每次增加 8 个非活跃项目。
- 搜索可以找到当前批次之外的项目。
- 隐藏项目不会触发 worktree 预取或差异统计请求。
- 分组计数、拖拽顺序、键盘操作和固定 Footer 主操作保持清晰且稳定。
